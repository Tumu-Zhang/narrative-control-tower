# 08 技能调度映射

## 一、真实加载原则

写作或校核任务开始前，必须**真实加载**与任务匹配的 skill（工具调用记录中存在真实的读取/加载动作，可在会话记录核验），再动笔。**仅口头声称"参考了相关规范"不视为调用。**

反面教训：某项目查验发现，此前多数写作与校核会话均未真实调用技能，仅文字声称参考——规则因此设立：自查验之日起必须真实调用，并在历次体检中抽查。

## 二、防滥用（同等重要）

- 仅当任务类型与 skill 职责匹配时加载；
- 纯整理、搬运、简单顺改类操作**不强制加载**；
- 不得为走形式加载无关 skill、不得把简单问题复杂化。

## 三、任务类型 → skill 映射（示例配置）

| 任务类型 | 加载 skill | 说明 |
|---|---|---|
| 试验数据章节写作（正交/优化/响应面/对比/表征） | `empirical-chapter` | 数据→结果→结论型内容的手法与体例，见配套 skill |
| 论证型内容（绪论、综述、分析、讨论） | 外部论证技能 | 按内容选型与接入方式见 [09-综述与论证章节](09-综述与论证章节.md)（"指路不打包"，保留原作者许可） |
| 整节/整章草稿重排 | 通用学术写作技能 | |
| 润色、改写、中译英 | 润色类技能 | |
| 引用支撑、文献检索核验、题录导出 | 文献检索/引用类技能 | |
| 科研绘图与图表审计 | 绘图类技能 | |
| 文献精读 | 精读/翻译类技能 | |

- 校核（体检/复核）任务按内容类型加载对应技能执行论证与写作方法审查——**校核窗与生产窗加载同一套技能，但各自独立运行**。
- 新增或更新技能一律统一安装到注册目录并验证**可真实加载**后方可视为可用；不得散装于其他目录仅靠口头引用。

## 四、用户手改与技能产出的关系

技能驱动脚本产出的任何文件，交付后即进入"手改保护协议"（references/06）管辖：重生成前 mtime 复检＋全量 diff＋差异必问。**技能是生产的起点，不是覆盖用户修改的授权。**

## 五、风格权重表：把用户反馈变成加权

对高频反馈型用户，建议维护一张**写作风格权重表**（放在 `00_项目管理/`）：

- 语料＝反馈目录全部文件＋历次校验报告（批评的两大登记落点）；
- 用词频统计脚本沉淀高频主题，分为两档：**T1 可枚举硬约束**（写作时逐项自检＋交付前机检）与 **T2 判断类**（每稿必控、人工把握）；
- 性质是**加权索引不是新增规则**：条款口径以总指令与任务约束为准，本表解决"写作时先盯什么、权重多大"；
- 与错误史联动：错误史管惩罚加权，本表管写作前置加权；反馈累积约 20 件重跑一次统计刷新。
