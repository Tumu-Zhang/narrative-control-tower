# 02 任务约束模板

小节级约束是整条管线的"唯一口径"载体。模板如下（字段可裁剪，但**写作目的、唯一数据源、小节结构、当前状态**四项不可缺）：

```markdown
# x.y 小节标题 任务约束

## 所属章节
第 N 章 ……

## 写作目的
本小节要回答什么问题、采用什么方法、达成什么结论（2~4 句，改写大纲时同步更新本段）。

## 唯一数据源
- 主数据表：<项目内相对路径>（结构与数值以重跑时实际核验为准，不预设结论）
- 辅助资料：<路径>（缺口登记于 source_notes.md）

## 数据口径（已裁决，本节沿用，不随数据版本变化）
- 口径 1：<定义、单位、阈值、惩罚/缺省规则>
- 口径 2：<样本单元、剔除规则、适用范围>
- 已废止表述：<明确列出不得再出现的旧说法>

## 方法学约定（与数据版本无关，重跑时须遵守）
1. <如：重要性排序以某统计方法为准，不得用模型输出反推>
2. <如：预测值必须来自交叉验证，不得用训练拟合值冒充>

## 小节结构
### x.y.1 …
- 内容 / 目的 / 数据需求 / 文献需求 / 图表需求

### x.y.2 …
- ……

## 当前状态
**<批次日期，窗口角色>**：<交付了什么、机检自查结果、下一步等谁>。
细节见 `数据与来源/source_notes.md` 与 `00_项目管理/执行日志.md` 同日条目。
```

## 写法要点

1. **口径条款写"裁决＋日期"**：每条口径标注裁决来源与日期，被取代的旧口径明确写"作废"，避免新旧并存。
2. **"以核验为准"原则**：数据表结构、列名、水平取值等不在约束里预设数值，一律写"以重跑时对实际内容的核验结果为准"，核验结果登记 source_notes——防止数据文件更新后约束变成假口径。
3. **当前状态只留最新批次详述**：历史批次状态移入"历史状态"小节归档，保证开工窗口一眼看到的是最新进度。
4. **约束修订流程**：任何窗口不得自行改写约束——先列冲突点与建议修订 → 用户确认 → 更新文件 → 在当前状态/执行日志留痕；涉及总指令条款的同步修订。

## source_notes.md 模板

```markdown
# x.y 数据与来源

## 已使用资料
| 资料 | 来源路径 | 核验日期 | 可支撑内容 | 处理状态 |
|---|---|---|---|---|

## 数据处理记录
<每次计算/清洗的口径、参数、产物路径，按日期倒序追加>

## 待补资料
<缺口清单：缺什么、谁补、状态>

## 已核验文献清单
| 临时编号 | 语言 | 题名 | 作者与年份 | 来源/DOI | 支撑位置 | 质量说明 |
|---|---|---|---|---|---|---|
```

要点：**每条文献必须说明支撑正文哪一类观点**，禁止泛泛列入；处理状态随小节状态跃迁同步改写（"草稿"→"正文"）。
