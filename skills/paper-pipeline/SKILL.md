# paper-pipeline —— 长文档 AI 协作生产控制管线

> 版本 v2.0（2026-10-19 公开泛化版）。源自一套实际运转两个多月、支撑六章硕士论文逐节生产的控制管线，剥离原项目内容后固化而成。前身为本仓库 `工程驾驭准备包/`（v1，面向单一 AI 编码窗口的宪法式准备包）；v2 将同一套控制思想升级为可装载的 Agent Skill。

## 一、解决什么问题

AI 长线协作生产会自然滑向四种失控模式，本管线逐一对应设防：

| 失控模式 | 典型表现 | 管线对策 |
|---|---|---|
| **口径漂移** | 多轮对话后同一参数/术语出现多个版本 | 小节常设 `任务约束.md` 唯一口径；开工必读、修订须作者确认（见 references/02） |
| **自产自检** | 生产窗口自己写、自己查、自己判合格、自己入库 | 生产/校核**窗口职责分离**，环节由用户逐环节转达（见 references/03） |
| **覆盖手改** | 脚本重生成静默覆盖用户已手改的文件 | 手改最高优先级协议：mtime 复检＋全量 diff＋编辑器暂存感知（见 references/06） |
| **状态失真** | 叙述性进度文档与磁盘实际落位脱节 | 状态看板以**磁盘落位为唯一真相源**，脚本生成、`--check/--write` 比对（见 references/05） |

## 二、总体架构

```text
项目根/
├─ 00_项目管理/            ← 总指令、状态看板.csv、执行日志、归档索引、已作废口径
├─ 01_范文与写法学习/
├─ 02_参考文献库/           ← 正文引用唯一来源 + 参考文献汇总表
├─ 03_文档框架/             ← 三级标题框架 = 正式审核门（框架未确认不写正文）
├─ 第一章 …/               ← 章节目录，下按小节分子目录
│   └─ x.y 小节/
│       ├─ 任务约束.md              ← 小节唯一口径（常设）
│       ├─ 数据与来源/source_notes.md ← 资料溯源与缺口登记（常设）
│       ├─ 草稿/  校验/  正文/  图表/  文献/   ← 按产出即时创建，禁预建空壳
├─ 图表总库/  数据整理/  最终汇总稿/
├─ 反馈/                   ← 用户反馈登记落点（风格权重表的语料来源）
└─ _工程/                  ← 脚本/检查报告/中间产物，与内容树隔离
```

**推进顺序**：先资料与文献 → 再框架审核（03 目录是正式门）→ 后分章按小节撰写。每个小节走 `草稿 → 校验 → 正文` 三级门控；生产、校核、整改、入库四个环节分属生产窗/校核窗，由用户逐环节转达。

## 三、十条硬约束红线

1. **框架先于正文**：三级标题框架经用户确认前，不进入任何章节正文撰写；结构变化先回改框架。
2. **约束是唯一口径**：小节动笔前必读 `任务约束.md`＋`source_notes.md`；任何窗口不得自行改写约束，冲突先列差异、经用户确认后更新并留痕。
3. **不编造**：正文必须以真实数据、已核验文献和用户提供的材料为依据；证据不足时输出**缺口清单＋待核验清单＋补充建议**，不得强行成文。
4. **逐节推进**：按章节、按小节推进，每天最多一个小节，宁缺毋滥；不一次性全文生成。
5. **窗口分离**：生产窗只写/只改，校核窗只查＋只登记；单次工作内禁止串联"生产→校核→整改→入库"（详见 references/03）。
6. **复核独立验证**：复核时逐项以实际文件内容独立验证，不采信报告自述；声明与文件不符必须在复核意见中记录。
7. **手改最高优先级**：覆盖式写入前 mtime 复检＋全量段落级 diff＋编辑器暂存检查；任何差异先呈用户确认（详见 references/06）。
8. **真实加载技能**：写作与校核前必须真实加载与任务匹配的 skill（会话记录可核验），口头声称"参考了规范"不算调用；纯整理搬运类任务不强制加载，防滥用（详见 references/08）。
9. **收尾三件套**：凡产生文件改动的任务，收尾前必须——①按批次追记执行日志；②状态看板 `--check`/`--write`；③小节状态跃迁同步 `任务约束.md`（详见 references/05）。
10. **目录纯净**：章节内容树内禁放工程脚本与归档产物；工程产物集中 `_工程/`，归档移出项目并登记索引；未声明位置的新文件一律外置。

## 四、开工与收工

**开工**（每个窗口固定动作，缺一不可）：
1. 读项目总指令（或等价的入口约束文件）→ 状态看板 → 本小节 `任务约束.md` → `source_notes.md`；
2. 开工状态自检：运行状态看板 `--check`（秒级、只读）；退出码 0 才开工；报差异先 `--write` 刷新并核对是否有小节状态与认知不符——保证任何窗口读到的进度不早于上一个任务；
3. 按"错误史/遗留待办"检索执行日志本节历史裁决，**已裁决事项不重问**。

**收工**（收尾三件套，见硬约束 9）：执行日志按**任务批次**追记（窗口角色＋改动文件清单＋遗留待办）→ 看板 `--check` 有差异即 `--write` → 小节状态跃迁回写约束。

## 六、维护

- v2.0（2026-10-19）：自原项目总指令、工作树与审核流程、体检校核实践、状态看板脚本、手改保护事故教训中泛化提炼；原论文相关口径、章节名、指标名与内部事件叙事全部剥离。
