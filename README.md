# narrative-control-tower · AI 生产控制塔

**把「让 AI 干活」变成「管住 AI 的交付」。**

一套实际运转了两个多月的 AI 协作生产控制方法，整理成可直接装载复用的 Agent Skills：
用**工程宪法**约束产出、用**阶段验收**卡住半成品、用**独立审查**防止自产自检、
用**状态看板**让进度以磁盘为准。两条产线共用同一套控制思想：

- **工程驾驭**（`工程驾驭准备包/`）：管 AI 写代码 —— 让它交付真实可运行、可验证、可审查的软件，
  而不是一个看起来能跑的空壳；
- **长文档生产**（`skills/paper-pipeline/`）：管 AI 写长文档 —— 管住多轮对话后的口径漂移、
  章节间自相矛盾、脚本重生成覆盖人改内容。

> 两条产线都来自真实项目：前者是面向 AI 编码窗口的治理准备包，后者支撑了六章硕士学位论文的
> 逐节生产。同源的「职责分离 + 阶段验收 + 全程留痕」思路，也用在两个开源桌面软件
> （[imgconv](https://github.com/Tumu-Zhang/imgconv)、[imgcrop](https://github.com/Tumu-Zhang/imgcrop)）
> 的 AI 协作开发流程里 —— 需求收集、开发、验收、发布分部门留痕。

## AI 生产会自然滑向的四种失控

| 失控模式 | 具体表现 | 对应的控制手段 |
|---|---|---|
| **自产自检** | 生产窗口自己写、自己查、自己宣布通过 | 独立审查线程：只审不写，专职找空壳、假交互、没调用模型 |
| **口径漂移** | 多轮对话后同一参数出现多个版本 | 约束文件是唯一口径，修订必须作者确认留痕 |
| **覆盖手改** | 脚本重生成静默覆盖用户改过的文件 | mtime 复检 + 全量 diff + 差异必问 |
| **状态失真** | 进度文档与磁盘实际脱节 | 状态看板由脚本按磁盘落位生成，`--check` 比对 |

## 30 秒看懂设计

| 原则 | 一句话 |
|---|---|
| 约束是唯一口径 | 常设 `任务约束.md`，修订必须作者确认留痕 |
| 三级质量门控 | 草稿 → 校验 → 正文，未经校验的稿件拒绝入库 |
| 窗口职责分离 | 生产窗只写、校核窗只查＋登记，禁止单窗串全流程 |
| 磁盘是唯一真相源 | 状态看板按磁盘落位生成，`--check` 比对 |
| 用户手改最高优先级 | 覆盖前 mtime 复检＋全量 diff＋差异必问 |
| 错误史机制 | 每次失败留痕并升级为检查项，同项再犯提高权重 |

## 快速开始

1. **安装**：把 `skills/` 下的目录复制到你所用 Agent 平台的技能目录
   （如 Claude Code 的 `.claude/skills/`、兼容 Agent Skills 规范的 `skills/` 路径），或按平台说明注册路径。
2. **新项目初始化**：按
   [`skills/paper-pipeline/references/01-项目工作树与初始化.md`](skills/paper-pipeline/references/01-项目工作树与初始化.md)
   搭建工作树，先落「总指令＋执行日志＋状态看板」三件。
3. **日常运转**：每个窗口开工跑 `status_board.py --check`；写作/校核按窗口职责分离转达；
   收工执行「收尾三件套」。
4. **写作**：数据章节装 `empirical-chapter`；绪论/综述/讨论章按
   [综述与论证章指南](skills/paper-pipeline/references/09-综述与论证章节.md)
   接入外部开源论证技能（K-Dense scientific-writing 等，MIT；指路不打包，许可随原作者）。

## 一条命令看状态

```bash
python skills/paper-pipeline/scripts/status_board.py --check    # 比对磁盘与看板
python skills/paper-pipeline/scripts/status_board.py --write    # 按磁盘重新生成看板
```
