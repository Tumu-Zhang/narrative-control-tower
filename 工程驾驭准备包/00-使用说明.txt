叙事中枢 / Narrative Control Tower 工程驾驭准备包

用途：
本准备包用于下一次新开 Codex 窗口时启动真正的软件工程，不继续修补当前原型。
它的目标不是描述一个好看的界面，而是约束 Codex 必须做出真实可运行、可验证、可审查的 agent 桌面软件。

建议使用顺序：
1. 先读 01-给Codex的工程宪法.txt。
2. 再读 06-用户真实诉求摘要.txt，先理解为什么不能做成空壳。
3. 再读 02-阶段验收清单.txt。
4. 新开主开发线程时，把 05-新窗口启动提示词.txt 作为第一条消息发给 Codex。
5. 当主开发线程完成一个阶段后，把代码、截图、日志和 03-独立审查线程说明.txt 发给独立审查线程。
6. 使用 04-插件与监督工具清单.txt 管理 git、GitHub、审查、验收和证据。

推荐工程控制结构：
本地 git 仓库：
保存每一次可靠进展，允许回看、比较、撤回和阶段封存。

GitHub 远程仓库：
作为云端备份、PR 审查、issue 管理、阶段标签和长期追踪平台。

Codex 主开发线程：
只负责设计、实现、运行、修复和提交，不自己给自己放行。

独立审查线程：
只负责审查，不参与主开发。它要主动找空壳、假交互、没调用模型、没读文件、没联网、没持久化、没权限门禁等问题。

阶段验收清单：
每一阶段必须通过清单后才能进入下一阶段。没有证据就视为未完成。

重要提醒：
当前已有 WinUI 原型只能作为反面经验和问题样本，不作为新工程的设计基础。
新工程必须从架构、数据、权限、模型调用、文件读写、验收流程重新建立。
