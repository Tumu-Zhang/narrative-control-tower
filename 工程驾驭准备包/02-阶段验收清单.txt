叙事中枢 / Narrative Control Tower 阶段验收清单

使用方式：
每完成一个阶段，主开发线程必须提交证据。
独立审查线程按本清单检查。
任何阻断项未通过，不进入下一阶段。

阶段 0：工程仓库与纪律
目标：
建立可追踪、可回退、可审查的工程基础。

必须完成：
1. 初始化本地 git 仓库。
2. 建立 GitHub 远程仓库。
3. 建立主分支和开发分支。
4. 写入工程宪法、阶段验收清单、审查线程说明。
5. 设置 .gitignore。
6. 明确构建方式、运行方式、测试方式。
7. 明确不继续沿用旧原型作为基础。

验收证据：
1. git status 输出。
2. git log 至少有一次初始提交。
3. GitHub 仓库地址。
4. README 中包含构建、运行、测试命令。

阻断项：
1. 没有 git。
2. 没有 GitHub 远程。
3. 没有阶段验收文档。
4. 没有明确技术栈。

阶段 1：真实项目系统
目标：
软件能创建、打开、保存本地项目文件夹。

必须完成：
1. 用户可以选择项目根目录。
2. 创建项目会生成真实本地文件夹。
3. 项目内生成 project.json 和标准子目录。
4. 软件能重新打开已有项目。
5. 左侧项目栏显示当前项目、路径、状态。
6. 设置中的输出目录和项目目录分开。
7. 修改项目数据后能落盘。

验收证据：
1. 创建项目的界面截图。
2. 本地文件夹截图或目录树输出。
3. project.json 内容片段。
4. 关闭重开后项目仍可读取的截图。

阻断项：
1. 只创建名字不创建文件夹。
2. 设置目录后不影响项目创建。
3. 数据只在内存存在。

阶段 2：运维模型与模型配置
目标：
建立真实模型调用路径，而不是本地硬编码匹配。

必须完成：
1. 首次使用要求配置运维模型。
2. 默认运维模型为 DeepSeek 系列。
3. 支持 API Key 保存、隐藏显示、删除重置。
4. 支持连接测试。
5. 没有 API Key 时明确禁用 agent 能力。
6. 模型搜索由运维模型或联网检索工具完成。
7. 搜索结果必须显示来源、置信度、用途建议。
8. 用户确认后才写入模型配置。
9. 支持角色绑定：运维、思考、写作、润色、检索分析、编程项目修改。
10. 支持懒人模式：所有角色使用运维模型。

验收证据：
1. 输入 kimi、gpt、mimo 等不同关键词时结果不同或明确无法确认。
2. 展示真实网络请求日志或模型调用日志。
3. 用户确认前配置文件不变化。
4. 用户确认后配置文件变化。
5. 连接失败时 UI 有明确错误。

阻断项：
1. 本地硬编码匹配。
2. 任意输入都匹配同一个模型。
3. 没有调用日志。
4. 没有 API Key 仍假装可生成。

阶段 3：权限系统
目标：
agent 不能随意读写、联网、删除或改正文。

必须完成：
1. 权限等级包括只读、询问、允许、拒绝。
2. 能配置读文件、写文件、改正文、改卡片、改设定、删除稿件、联网检索、安装 skill、执行脚本、调用外部 API。
3. 敏感动作弹出权限确认。
4. 弹窗显示动作、发起者、影响范围、涉及文件、风险。
5. 支持允许一次、拒绝、总是允许、进入设置。
6. 权限决定写入日志。

验收证据：
1. 尝试入正文库时出现权限弹窗。
2. 尝试删除稿件时出现权限弹窗。
3. 拒绝后动作不发生。
4. 允许后动作发生并写日志。

阻断项：
1. 模型可直接改正文。
2. 删除不确认。
3. 权限设置只是 UI，实际不拦截。

阶段 4：资料库真实摄取
目标：
资料库能真实读取本地文件和联网检索。

必须完成：
1. 支持本地 txt、md、docx、pdf 的文本读取。
2. 支持粘贴文本分析。
3. 支持 URL 读取或检索。
4. 支持关键词和作品名检索。
5. 分析由运维模型或检索分析模型完成。
6. 输出区分软件理解版、客户审核版、可学习内容、不可照搬内容、风险、可绑定对象。
7. 对不同输入必须输出不同分析。
8. 读取失败、权限不足、联网失败必须明确报错。

验收证据：
1. 输入本地文件路径后显示读取到的标题、字数或片段摘要。
2. 输入作品名后显示检索来源。
3. 两个不同输入输出明显不同。
4. 分析结果落盘到 references 目录。

阻断项：
1. 只读取路径字符串。
2. 不同输入同一模板。
3. 没有模型或检索调用日志。

阶段 5：创作资产与连锁修改
目标：
人物卡、剧情、设定、伏笔、章节、资料之间建立依赖图。

必须完成：
1. 支持人物卡、事物卡、地点、机构、特殊设定。
2. 人物卡按出场频率和剧情权重自动分级 S/A/B/C。
3. 支持剧情节点、冲突链、伏笔、回收状态、主线、暗线、副线。
4. 修改卡片或剧情前生成 ChangeSet。
5. ChangeSet 显示直接影响、间接影响、风险、同步项。
6. 用户确认后才应用。
7. 应用失败或部分应用可回滚。

验收证据：
1. 修改人物卡触发 ChangeSet 预览。
2. 修改剧情节点显示影响章节和伏笔。
3. 确认后文件变化。
4. 回滚后文件恢复。

阻断项：
1. 只改一个文件不检查关联。
2. ChangeSet 只是文字说明不参与应用。
3. 没有回滚记录。

阶段 6：章节生产真实工作流
目标：
章节生产必须由思考模型策略驱动写作模型生成候选稿。

必须完成：
1. 生产中心四页完整。
2. 第一页宏观控制可保存。
3. 第二页章节任务可保存。
4. 第三页 AI 建议基于第一页和第二页内容生成。
5. 用户确认后的建议才进入控制单。
6. 思考模型生成章节策略。
7. 写作模型根据策略生成候选稿。
8. 写作模型不能绕过思考模型。
9. 自动审核生成风险报告。
10. 人工审核可选择入正文、局部小修、删除。
11. 删除必须填写原因和整改方向并进入废稿库。

验收证据：
1. 模型调用日志显示思考模型先执行。
2. 候选稿文件写入 drafts。
3. 审核报告写入 reviews。
4. 删除稿件进入 waste，不参与上下文。
5. 入正文库生成事务记录。

阻断项：
1. 章节生成只套模板。
2. 没有模型调用日志。
3. 没有用户确认就入库。
4. 废稿仍参与上下文。

阶段 7：UI 与交互可用性
目标：
界面不是堆控件，而是可长期使用的桌面软件。

必须完成：
1. 窗口最大化时主内容区合理铺满。
2. 缩小窗口时 UI 自适应，不重叠，不遮挡。
3. 右侧上下文面板有实际关系信息。
4. 状态栏、主导航、侧栏职责不重复。
5. 设置中心集中管理基础、模型、权限、skills、输出、外观、支持。
6. 外观设置真实生效。
7. 左侧侧边栏层级、对比度、字号清晰。
8. 可点击控件必须有状态变化或实际结果。

验收证据：
1. 最大化截图。
2. 小窗口截图。
3. 设置切换截图。
4. 外观切换前后截图。
5. 关键按钮点击后状态变化截图。

阻断项：
1. 文字重叠。
2. 右侧大片空白。
3. 滚动条遮挡 UI。
4. 大量按钮不可用但没有禁用态或说明。

阶段 8：打包与第一版发布
目标：
软件可安装或可独立运行。

必须完成：
1. Release 构建成功。
2. 能在干净目录运行。
3. 配置、项目、日志位置清楚。
4. README 写明安装、启动、配置运维模型、创建项目。
5. 第一版已知限制列出。

验收证据：
1. Release 构建日志。
2. 安装包或发布目录。
3. 首次启动截图。
4. README。

阻断项：
1. 只能在开发环境启动。
2. 关键配置路径不清楚。
3. 无法创建新项目。
