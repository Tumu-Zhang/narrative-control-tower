给 Codex 的工程宪法：叙事中枢 / Narrative Control Tower

一、总原则
本项目要制作的是一个 Windows 桌面 agent 软件，不是静态 UI 演示，也不是问答式小说生成器。
软件必须能创建本地项目、读取项目、修改项目、管理创作资产、控制章节生产、审核候选稿、维护正文库，并通过连锁修改机制检查和同步相关点。

如果某个功能只是按钮、模板文本、假数据、硬编码匹配或不可验证的演示，不能算完成。
如果没有真实文件读写、真实持久化、真实权限门禁、真实模型调用路径，不能算完成。

二、禁止事项
禁止把软件做成空壳：
1. 禁止只做 UI，不做业务逻辑。
2. 禁止按钮可点但没有真实效果。
3. 禁止把模型检索做成本地硬编码匹配。
4. 禁止用户输入任意模型名时都匹配到固定模型。
5. 禁止章节生成只套 skills 模板而不调用模型。
6. 禁止资料库只读取路径字符串而不读取本地文件内容。
7. 禁止资料库对不同输入输出同一套分析模板。
8. 禁止设置保存后不影响项目目录、输出目录或运行行为。
9. 禁止未经过用户确认就写入模型配置。
10. 禁止未经过用户确认就入正文库、删除稿件或批量连锁修改。
11. 禁止用“准备就绪”反复刷屏代替真实状态。
12. 禁止未构建、未启动、未截图、未关键交互验证就宣布完成。

三、软件核心身份
软件不是“小说聊天机器人”，而是“创作工程控制塔”。
它的执行层是 agent harness：
1. 有模型角色。
2. 有权限系统。
3. 有项目文件系统。
4. 有创作资产库。
5. 有章节生产工作流。
6. 有资料摄取与分析。
7. 有候选稿、审核、正文、废稿隔离。
8. 有 ChangeSet 连锁修改机制。
9. 有可回滚的事务式入库。
10. 有证据、日志和验收记录。

四、运维模型逻辑
软件首次启动时，必须先配置运维模型。
默认运维模型只允许 DeepSeek 系列，目标名称暂定 deepseek-v4-pro。
运维模型是软件的基础执行脑，用于：
1. 检索和识别其他模型。
2. 解释模型能力、价格、上下文、API 兼容性。
3. 辅助部署思考模型、写作模型、润色模型、检索分析模型、编程项目修改模型。
4. 读取资料、分析内容、规划任务、生成控制单。
5. 驱动权限受控的 agent 工作流。

运维模型不是用户后续创作必须一直使用的唯一模型，但离开运维模型，软件不能伪装自己可以工作。
如果运维模型没有 API Key 或连接失败，软件必须明确显示“agent 执行能力不可用”，只能使用离线项目管理功能。

五、模型配置规则
模型配置必须遵循：
1. 用户输入模型名称。
2. 软件调用运维模型进行联网检索或调用可信模型目录 API。
3. 软件显示检索结果、来源、置信度、模型用途建议。
4. 软件询问用户：是否确认这是要安装的模型。
5. 用户确认后才写入配置。
6. 用户输入该模型的 API Key。
7. 软件测试连接。
8. 连接成功后才允许绑定到角色。

至少要支持这些模型角色：
1. 运维模型。
2. 思考模型。
3. 写作模型。
4. 润色模型。
5. 检索/分析模型。
6. 编程/项目修改模型。

允许懒人模式：
用户可以选择全部角色暂时由运维模型承担。
但 UI 必须清楚显示这是“全部使用运维模型”的模式，而不是已经部署了多个模型。

六、权限系统规则
所有 agent 动作必须经过权限层。
权限等级包括：只读、询问、允许、拒绝。

必须可配置的权限至少包括：
1. 读文件。
2. 写文件。
3. 修改正文。
4. 修改人物卡。
5. 修改设定。
6. 删除稿件。
7. 联网检索。
8. 安装 skill。
9. 执行脚本。
10. 调用外部 API。
11. 批量连锁修改。

必须强制人工确认的动作：
1. 进入正文库。
2. 修改正典。
3. 删除稿件。
4. 批量连锁修改。
5. 写入或覆盖模型配置。
6. 安装或执行外部 skill。

权限弹窗必须显示：
1. 当前动作。
2. 发起模型或模块。
3. 影响范围。
4. 涉及文件和创作资产。
5. 风险说明。
6. 允许一次、拒绝、总是允许、进入设置。

七、项目文件规则
创建项目必须创建本地文件夹，而不是只创建一个名字。
项目根目录必须可由用户指定。
项目内必须有清晰结构，至少包括：
1. project.json 项目清单。
2. cards 人物卡、事物卡、地点、机构、特殊设定。
3. plot 剧情节点、主线、暗线、副线、伏笔。
4. production 章节任务、控制单、AI 建议、用户确认记录。
5. drafts 候选稿。
6. canon 正文库。
7. reviews 审核报告。
8. references 资料库。
9. changesets 连锁修改记录。
10. waste 废稿隔离库。
11. logs agent 执行日志。
12. settings 项目级配置。

输出目录和项目目录必须区分。
设置中的默认输出目录不能偷偷替代项目根目录。

八、资料库规则
资料库必须支持：
1. 本地文件。
2. 粘贴文本。
3. URL。
4. 关键词。
5. 作品名。

本地文件必须实际读取内容。
URL 和作品名必须通过运维模型或检索工具联网检索。
如果没有权限、没有 API Key、无法联网或文件读取失败，必须明确报错，不得输出假分析。

资料库输出必须区分：
1. 软件理解版。
2. 客户审核版。
3. 可学习内容。
4. 不可照搬内容。
5. 抄袭/过拟合风险。
6. 可绑定对象：章节、卡片、剧情节点、文风控制。

九、章节生产工作流
章节生产必须严格执行：
宏观输入 -> 章节任务 -> AI 理解建议与用户反馈 -> 思考模型生成章节策略 -> 写作模型生成候选稿 -> 自动审核 -> 人工审核 -> 局部小修或删除 -> 入正文库。

写作模型不能绕过思考模型策略。
润色模型不能擅自改剧情、设定、人物动机，除非用户明确提升为连锁修改。
用户确认后的 AI 建议才能进入控制单。

十、入库事务规则
入正文库必须是事务式操作。
一次入库至少同时记录：
1. 候选稿。
2. 质量报告。
3. AI 主观阅读卡。
4. 控制单。
5. 人物变化。
6. 关系变化。
7. 章节摘要。
8. 伏笔变化。
9. 权限确认记录。
10. 事务日志。

以下情况必须阻断入库：
1. 缺失声明。
2. 角色 ID 缺失。
3. 研究或参考依据缺失。
4. 字数超限。
5. 废稿未隔离。
6. 自动审核未完成。
7. 人工确认缺失。
8. 连锁修改未预览。

十一、连锁修改机制
任何修改不能只改一个点。
修改人物卡、剧情、设定、章节、正文、文风、资料绑定、门禁或负面提示词前，必须生成 ChangeSet。

ChangeSet 必须显示：
1. 直接影响。
2. 间接影响。
3. 关联资产。
4. 风险。
5. 需要同步修改的项。
6. 用户确认状态。
7. 应用结果。
8. 回滚信息。

失败或部分应用必须可回滚。

十二、UI 规则
界面必须能适应窗口最大化和缩小。
不能右侧大片空白。
不能文字重叠。
不能滚动条遮挡 UI。
不能状态栏和导航栏重复。
设置中心必须集中管理基础、模型、权限、skills、输出、外观、支持。
AI 控制台和 skills 管理既然集成在设置中心，就不要再出现在主导航。

主导航只保留业务主模块：
1. 总控台。
2. 卡片库。
3. 剧情库。
4. 生产中心。
5. 书架。
6. 废稿库。
7. 资料库。

十三、skills 规则
内置 skills 不再在普通界面密集陈列。
软件保留一个“打开内置 skills 文件夹”入口。
进入前必须提醒：
内置 skills 会影响生成效果，修改后可能导致章节生产、审核或入库异常，请谨慎修改。

必须提供“恢复内置 skills”按钮。
恢复按钮要能从软件自带基础包一键恢复。

十四、验收规则
每个阶段必须提供：
1. 构建命令和结果。
2. 启动命令和结果。
3. 关键交互截图。
4. 关键日志。
5. 数据文件变化证据。
6. 测试结果。
7. 未完成项清单。

没有证据，不算完成。
